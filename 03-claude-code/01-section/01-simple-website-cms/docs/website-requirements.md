I want to add a new feature to my existing plain Node.js application.

## Goal

I want to turn the existing website into a very simple server-rendered website with two areas:

### 1. Client area

Visitors should be able to view normal HTML pages created by the administrator.

For example:

GET /
GET /pages/about-us
GET /pages/contact

These should be normal server-rendered pages.

Do NOT create a SPA.

Do NOT introduce React, Vue, Angular, client-side routing, or another frontend framework.

Small amounts of JavaScript are fine where necessary.

### 2. Admin area

Create a simple admin area where I can manage website content.

The administrator should eventually be able to:

- create pages
- edit pages
- delete pages
- view existing pages
- upload photos
- organize photos into different folders
- select/use uploaded photos in pages

I want the admin area to also be traditional server-rendered HTML pages, not a SPA.

For example:

GET /admin
GET /admin/pages
GET /admin/pages/create
GET /admin/pages/edit/:id
GET /admin/uploads

Use normal HTML forms and normal HTTP requests.

## Dynamic pages

An administrator should be able to create a page with fields such as:

- title
- slug
- description
- main image
- CKEditor content
- other simple fields where appropriate

For example:

Title:
About Us

Slug:
about-us

Description:
Information about our company.

Main image:
uploads/pages/about.jpg

Content:
HTML produced by CKEditor.

A visitor should then be able to visit:

/pages/about-us

and receive a normal server-rendered HTML page using the stored page data.

## CKEditor

Use CKEditor as the rich-text editor for the page content.

The editor should be part of a normal HTML form.

When the form is submitted, the server should receive the HTML content generated by CKEditor and store it with the page.

Do not build a custom rich-text editor.

Do not make the entire application client-side just because CKEditor uses JavaScript.

## Photo uploads

The admin area should allow uploading photos.

Photos should be stored on the server filesystem, not inside the database.

I want photos to be organized into different folders/categories.

For example:

uploads/
general/
pages/
gallery/

The exact folder structure can be discussed after you inspect the existing project.

The database should store the relevant filename/path when a photo is associated with a page.

Implement basic validation so that users cannot use arbitrary filesystem paths or upload inappropriate file types.
